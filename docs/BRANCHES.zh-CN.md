# PageNote 分支地图

2026-10-30 整理：长期维护线只有下列六条。`codex/*` 是任务期间的临时分支，PR 完成后删除；历史归档使用标签，不再作为日常开发线。

| 分支 | 职责 | 可以接收什么 |
| --- | --- | --- |
| main | 已批准的稳定历史与项目导航 | 经批准的稳定变更；单独审查的导航文档更新 |
| beta | 共享格式、桌面共用逻辑、跨平台集成 | 共享功能 PR；不是所有系统同时发布 |
| windows/main | Windows 已批准稳定线 | Windows 晋级 PR，须发起人针对该次批准 |
| windows/beta | Windows 平台测试线 | Windows 功能、适配、文档和经审查的共享同步 |
| macos/beta | Mac 实验性平台线 | Mac 功能、适配、文档和待验证共享同步 |
| android/beta | Android 独立实现测试线 | Android 功能、文档和格式同步 |

Mac 与 Android 尚无获批稳定基线，因此暂不建 macos/main、android/main。Linux、鸿蒙仍未开发，不预建空分支。版本配置中的空稳定线必须为 null，不能给出不存在的链接。

## 一个平台更新时怎么走

Windows 私有修改：从 windows/beta 开临时分支，PR 回 windows/beta；只更新 Windows 的版本、说明和制品。共享修改：从 beta 开临时分支，PR 回 beta，再分别通过同步 PR 送到受影响的平台。其他平台的版本和下载不自动改变。

同步 PR 必须注明源提交、文件范围、冲突处理、实际平台验证与未同步原因。平台之间不整支互相合并；共享线同步也不能借机把未经批准代码推到任何 main。平台分支的根 README 只介绍该系统，并链接该系统的 docs/<platform>/README.md；共享线根 README 只做项目导航。

## 与最初架构的差距

| 要求 | 当前情况 |
| --- | --- |
| 各系统独立 README、教程／截图、更新说明 | 已建目录，本轮将文字按平台重写；Mac／Android 模块截图仍有缺口 |
| 各系统独立版本与打包入口 | 已建；公开下载继续固定最后完整发布包 |
| 各系统 main／beta | Windows 已有；Mac／Android 缺稳定批准，不伪造正式线 |
| 清晰源码边界 | Windows／Mac 入口已分开，src 与 desktop 仍共享；Android 仍为独立 android/ 工程，未全部搬迁 |
| 共享代码持续同步平台线 | 此前平台线停留在整合基线，未持续执行；本轮按平台同步及文档 PR 补齐，不宣称所有平台通过 |
| 平台标签与自动发布 | 尚未完成全套新标签发布迁移，不因为创建分支就宣称已上线 |
| 分支保护与自动清理 | 不能把要求文档等同已配置的 GitHub 保护；本轮执行人工审计与有备份的清理 |

因此此前是**部分落实**，并非完整的平台自治架构。不要为了目录整齐重写已经运行的软件，也不要让平台分支成为长时间不更新的装饰。

## 本轮清理及恢复

已移除五条完成的 codex 远端任务分支，以及四条稳定文档／修复分支。后四条是历史压缩合并，已通过 patch 等价核对；不能只凭“不是祖先”就宣称工作丢失。九条旧分支均先建立 archive/2026-10-30/<原分支名> 归档标签，完整来源见 [归档清单](BRANCH-ARCHIVE-2026-10-30.json)。这些是恢复标签，不是软件 Release。

恢复示例：git switch -c codex/recover-old-work archive/2026-10-30/codex/markdown-s-visual-lab。

本地旧分支另存为 archive/2026-10-30/local/<原分支名> 标签；旧工作树转为同一提交的 detached HEAD，文件与未提交修改保持原样。归档不是删除源码、项目或历史标签。

每次合并后核对无后续工作再删临时分支；每次推送更新 CHANGELOG。用 git fetch --prune 清理已经不存在的远端引用，避免把本地缓存误认为远端实际分支。当前仓库已启用本地 fetch.prune。
