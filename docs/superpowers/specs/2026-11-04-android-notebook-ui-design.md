# Android 笔记工作区与无感保存设计

## 意图

把 PageNote Android 做成一款以课件、笔记和画布为中心的平板笔记软件。横屏时充分利用页面并列阅读原文和笔记；常用笔工具可以浮在内容上方并快速收起；Agent 是 PageNote 的特色能力，但保持按需打开，不常驻挤压阅读区。文字编辑应自动写回当前项目，普通保存不打断用户；翻页、回书架或打开另一个项目之前必须确保当前草稿已经安全写回。

## 目标与边界

### 目标

- 重新梳理 Android 书架、阅读器、笔记编辑及各模块面板的视觉层级与导航；内容优先，系统状态栏和手势区域处理稳定。
- 平板横屏保留可调节的原文／笔记双栏。阅读、编辑、画布和页面浏览使用一致的项目标题与简洁导航。
- 笔盒作为阅读器窗口内的浮动工具面板，能够拖动、靠边吸附、展开设置和收为小球；不要求用户授予“显示在其他应用上层”权限。
- 页面缩略图／页栏从一侧开合。Agent 工作区以同类可关闭的侧边面板进入；关闭或系统返回后，回到原来的页面、选区和滚动位置。两个侧栏互斥，避免彼此覆盖。
- 笔记草稿停止输入后自动保存。保存成功不显示 Toast、Snackbar 或“已保存”提示；只有实际错误、冲突或需要用户处理时显示明确的行内状态和下一步操作。
- 翻页、返回书架、系统返回、离开当前项目均先等待当前页面草稿写回成功。写入失败时留在当前页，不覆盖旧文件，保留本地草稿并允许重试。
- 窄屏和竖屏下避免把原文、笔记和侧栏压缩成难以阅读的细列；提供明确的“原文／笔记”切换，工具入口仍可达。

### 不做的事

- 不移植参考应用的图标、品牌、文字、资源或实现代码；仅借鉴其平板画布优先、笔盒可移动／可停靠、工具按需出现的交互思路。
- 不改项目文件格式、PDF／Markdown 数据、批注与笔迹模型、Agent 服务协议、Android 权限或其它平台 UI。
- 不以 UI 重做名义改变 OCR、录音、雨课堂、Office、闪卡等模块的业务行为。次级模块采用统一的 PageNote 面板样式，逐模块功能和接通状态仍以现有能力为准。
- 不把 Agent 改为默认主页或常驻栏；不增加新的云同步或后台服务。

## 方案比较与选择

1. **保留现有双栏并收拾工具栏**：改动少、回归风险低，但阅读器和笔记仍被固定 chrome 占据，小屏两栏仍可能拥挤。
2. **单画布全屏模式**：空间最大，接近触控笔记软件；但原文／笔记来回切换成本高，削弱 PageNote 的课件逐页对照特色。
3. **自适应笔记工作区（已选）**：横屏保留原文／笔记双栏，精简固定栏；页栏和 Agent 用互斥侧边面板覆盖打开；笔盒作为应用内浮动面板；窄屏改为原文／笔记单页切换。保留当前产品的逐页对照，并让工具按需出现，最符合用户选定的方向。

## 界面草图

### 平板横屏：双栏为主，面板按需覆盖

```text
┌ 系统状态栏 ───────────────────────────────────────────────────────────┐
│ ‹  项目名／当前页                         页码 ▾     Agent ◉   ⋯       │
├─────────────────────────────┬────────────────────────────────────────┤
│                             │  笔记   编辑／预览     历史               │
│        课件／PDF             │                                        │
│                             │        当前页笔记                       │
│                             │                                        │
│              ┌笔盒────────┐ │                                        │
│              │笔  色  粗细 │ │                                        │
│              └────────────┘ │                                        │
├─────────────────────────────┴────────────────────────────────────────┤
│ 低存在感的阅读状态／工具状态；正常保存不显示成功文案                 │
└──────────────────────────────────────────────────────────────────────┘

打开 Agent 后：
┌────────────原文／笔记原位保留─────────────┬── Agent 工作区 ──×───┐
│ 当前页、选区、滚动位置不丢失             │ 现有 Agent 能力入口  │
└──────────────────────────────────────────┴─────────────────────┘
```

页码入口展开原文页栏；Agent 按钮展开 Agent 侧栏。面板打开时暂时盖住一部分内容，不强迫原文和笔记重排；关闭后恢复原工作区。系统返回先关闭最上层面板，再执行外层导航。

### 竖屏／窄窗口：一次聚焦一种内容

```text
┌ 项目名                    Agent ◉  ⋯ ┐
│  [ 原文 ] [ 笔记 ]                    │
│                                        │
│             当前内容                  │
│                                        │
│  [可移动的笔盒／收起球]       页码 ▾   │
└────────────────────────────────────────┘
```

当有效内容宽度不足以维持两侧可读时，不保留窄双栏。页栏和 Agent 依旧从侧边开合；软键盘出现时主编辑区滚动到光标，笔盒避让键盘。

## 交互细节

### 主要工作区

- 书架提供可读的项目卡片、最近打开入口、导入／新建／选择目录操作；不把设置和少用功能放在与“打开笔记”同等显眼的位置。
- 阅读页标题栏只保留返回、项目／页码、缩放（PDF 时）、Agent 和“更多”入口。编辑与预览在笔记区域内切换；页码入口同时负责开关页栏。移除需要用户定期点击的显式“保存”按钮；保存过程仅在必要时显示小型进行中标记。
- 横屏双栏中间保留可拖动分隔线；沿用项目当前的持久化双栏比例。调整范围保证两边都能实际阅读，不覆盖原文或笔记。
- 工具、对话、识别和项目设置使用统一表面、间距、图标触控区和关闭行为；保留现有功能名称和具体业务反馈。

### 浮动笔盒

- 笔盒位于应用阅读窗口合成层，而不是 Android `SYSTEM_ALERT_WINDOW` 系统层；不覆盖其它应用。
- 提供清楚的拖动握柄、边缘吸附和轻触展开／收起。拖动握柄以外的区域仍可触控笔型、颜色、粗细、橡皮及选择工具。
- 展开时只显示当前工具需要的控制项；颜色／粗细选择按需展开，避免一条常驻工具带占满 PDF 边缘。
- 状态从应用现有笔工具状态读取；面板重建、侧栏开关或屏幕旋转不能改变当前笔迹工具和绘制状态。位置只保存为阅读 UI 偏好，夹在当前可视边界内；不写入项目内容。
- 保留可访问的工具名称、足够触控尺寸、对比度及键盘／屏幕阅读器入口。浮动位置避开页码、编辑焦点和软键盘。

### 页栏与 Agent 侧栏

- 页面栏与 Agent 使用同一侧栏容器和开合手势，但各自从适合其入口的一侧出现；任一时刻只显示其中一个。软键盘可见时系统返回优先收起键盘，不能因第一次返回而离开项目。
- 侧栏为阅读窗口内的滑入面板，明确提供关闭按钮，支持系统返回、触控外部关闭和再次点击入口关闭。用户选择页后收起页栏并回到所选页。
- Agent 沿用当前已实现的 Android 功能入口、会话、模型配置和权限限制；本次只调整入口及呈现，不假定桌面 MCP 能力已移植到 Android。
- 打开与关闭 Agent 不切页、不保存一个不存在的草稿、不改变编辑区内容；若其某个现有子流程确实改动笔记，复用本页自动保存与错误处理规则。

### 无感自动保存和安全导航

1. 编辑器把每次文本变化写入会话草稿和现有本地恢复记录。停止输入约700毫秒后，对当前 `project + page + revision` 执行有序文件保存；持续输入时最多每3秒保存一个最新快照。不把恢复日志误当成项目文件已经保存。
2. 一次保存进行时的新输入保留为较新的草稿版本。旧版本写完后必须再次写最新版本；只有草稿与项目文件页内容及 revision 一致时，才把该页视为已保存。
3. 普通成功不触发 `noteStatus` 成功文案、Toast 或 Snackbar。可以保留极小的保存中指示和未保存小点，但它们不打断输入、不抢焦点，也不宣称成功。
4. 点击翻页、选页或回书架时，先冻结这次导航的目标并立即 flush 当前草稿，不等待普通自动保存计时器。保存期间继续留在原页；写入成功后再应用目标导航。快速重复点击不得让目标页错乱。
5. 返回按钮和 Android 系统返回遵循同一顺序：先关闭 Agent／页栏等内层面板，再 flush 草稿，之后才退出项目。点击书架上的其他项目也先完成当前草稿保存。
6. 写入失败或 revision 冲突时，不移动页面、不清空草稿、不刷新成外部旧内容。保存状态留在笔记区域附近，提供简洁错误原因和重试／冲突处理入口；原有恢复副本保持可恢复。普通编辑不能因错误提示自动丢弃本地内容。
7. 若当前文档只读或用户撤销了 SAF 授权，保存失败状态必须解释下一步，保留内存草稿和本机恢复副本；不能冒称已写回项目。

## 技术约束与可由实现者决定的部分

- 以 `android/beta` 当前 Compose、`ReaderSessionViewModel`、SAF `ProjectNoteStore`、revision 受检写入和草稿恢复设施为基础。UI 重构不得绕过 `PageNoteEditor.replacePage` 的 revision 检查，也不得把跨页分隔符写坏。
- 侧栏动画时间、精确 dp 间距／颜色 token 属实现选择，默认以输入响应和正常编辑无打断为准；低延迟输入期间不能同步阻塞 UI 线程。
- 自动保存与显式手工保存最终走同一有序保存协调器，避免两个协程读相同旧 revision 后互相覆盖。
- Agent、页栏、书架和面板状态放在恰当的 UI/session state。除非目前已有用户偏好字段，不把临时抽屉开合、选择页、浮动位置写进项目格式。
- 先将主工作区、浮动笔盒、侧栏状态和保存协调分离为可读的小 composable／state holder；不要为了新视觉一次重写大型 `MainActivity.kt` 中的 PDF 绘制、OCR 或笔迹保存内核。

| AND-UI-05 | Agent 侧栏从入口打开并可由关闭按钮、系统返回或再次点击入口关闭；它覆盖而不破坏当前页和笔记草稿。 |

## 主要风险及处理

- **保存并发与冲突**：创建统一当前页 flush 通道并合并新草稿版本，延用 revision 冲突检测；导航仅在 flush 返回成功时提交。
- **系统返回、菜单及项目切换入口遗漏**：列举所有离开当前项目的回调，统一调用同一会话导航函数；面板开着时系统返回先关闭面板。
- **浮动面板误触和挡住课件**：拖动只认握柄；位置可还原、收小；旋转／分屏时将坐标夹紧到有效窗口。
- **过大的单文件 UI 改动引入回归**：先提取必要的 reader shell、palette、drawer、autosave state holder，逐阶段接入现有渲染／笔迹视图，避免触碰其数据模型。
- **Android beta 分支晚于共享 beta**：实现以 `android/beta` 为基线，不 cherry-pick PR #27 的跨平台文档提交作为运行依赖；如确需共享服务改动，单独记录来源与同步。
