# 桌面书架需求

日期：2026-10-22（Asia/Shanghai）

状态：用户已确认并授权实现；桌面共用实现已完成，Mac arm64 定向验证见 [记录](validation.md)。Windows 运行未验证。

## 目标与范围

将已确认的 [Android 书架](../../../android/docs/spec/features/bookshelf-home.md)
同步到 Windows 和 macOS，复用其书架式封面网格、纸本配色和自定义行为。
桌面两端复用现有 Electron 主体，不复制 Android 原生代码，不重新设计阅读器。
用户可在统一目录管理项目，启动即可选书阅读，新建项目自动加入书架。

本次“同步”指功能和项目封面数据兼容，不引入跨设备文件同步服务。

## R1 绑定目录与自动发现

- 当用户尚未绑定目录而正常启动应用时，应用应显示书架和系统目录选择入口；取消选择不得记录为绑定成功。
- 当绑定成功时，应用应在本机保存目录设置，以后启动无需重复选择；Windows 与 Mac 各自绑定本机目录，不将机器绝对路径写入项目。
- 当启动、回到书架、窗口重新激活或项目新建/导入完成时，应用应重新扫描绑定目录；同时保留手动刷新入口。
- 扫描应递归查找标准项目，识别项目后不再进入其 src、附件、历史或缓存目录；保留已有旧格式项目的打开能力。
- 当目录不可访问或已删除时，应用应显示可恢复错误及重新选择入口，不将失败显示为“空书架”。个别损坏项目应警告但不阻止其他项目显示。
- 扫描深度上限为 8 层、目录数上限为 2,000、单目录条目上限为 10,000；触及上限应说明结果不完整。扫描不得提前加载全部源文档或运行 Office 转换。
- 当用户在设置中更换目录时，应用应显示当前路径并允许重新选择，但不搬移、删除旧项目；已有外部项目仍可通过原入口打开。

## R2 首页与阅读入口

- 当应用正常冷启动时，应用应进入书架，不自动进入上次阅读器；当用户双击项目文件、使用“打开项目”或由现有文档控制接口显式打开文档时，应保留直接打开行为。
- 书架应复用 Android 的封面网格、横向层板、封面下方名称及日期、每本书的更多菜单，并提供列表视图。
- 书架应提供新建、导入文档、搜索、按最近更新/名称排序、刷新及设置。封面与标题区域应尺寸稳定，长名称不挤压相邻项目。
- 当用户选书时，应用应使用现有项目打开流程，并恢复该项目阅读位置及现有可恢复草稿；发现项目不能只依赖“最近文档”缓存。
- 阅读器应提供清晰的返回书架入口，原有菜单、双栏、AI、批注和编辑功能继续保留。
- 当用户返回书架时，应用应先通过现有保存流程完成笔记、文稿及笔迹写入；保存失败时应留在阅读器并提示，不得丢弃草稿。
- 当书架显示时，应用不应因隐藏的上一本书继续进行无必要的页面渲染或 OCR 预取；已明确启动的雨课堂采集不得被静默终止。

## R3 默认封面与自定义

- PDF 项目应默认使用第一页完整缩略图，采用适应封面而非裁切内容的方式；Markdown 项目应使用写有 `Note` 的纸本封面，实际书名显示在封面下方。
- 默认纸本保留 Android 的 sage、rose、sky、graphite 四种配色；无需为桌面另造一套封面风格。
- 用户应能修改显示书名、选择本地图片、指定 PDF 封面页、切换纸本配色及恢复默认；这些修改不得更改源文档、项目文件夹名称或分页对应关系。
- 封面设置应兼容 Android 的可选 `src/bookshelf.json` v1：`title`、`cover`、`asset`、从零开始的 `page`、`paper`；缺失或损坏时回退默认并保留项目可打开性。
- 自定义图片应复制进项目 `src/assets/`，元数据只记录安全文件名，不依赖原图片选择位置；不得读取越界路径或通过符号链接读取项目外资源。
- 缩略图应异步、按需加载，限制并发和缓存容量，并随文件或封面设置变化失效；失败时应保留可打开的书及可识别的封面错误状态。
- 若项目来源是桌面特有的 Word/PPT，应复用已有 PDF 预览作为封面；尚无有效预览时显示通用封面，不在扫描过程中调用 Office。

## R4 新建与导入

- 当绑定目录存在时，普通新建、书架文档导入、雨课堂历史导入和新建实时采集项目应默认使用该目录，不再每次强制选择父目录；用户仍可显式选择其他目录。
- 当用户从书架导入独立 PDF/Markdown 时，应用应创建标准项目并复制原文，不将该操作误解为替换上一本书的左侧文稿。
- 当用户在阅读器内使用现有“导入左侧”时，应用应保留现有替换行为，与书架“导入文档”区分。
- 当新建或导入成功时，项目应在书架刷新后自动出现并可在重启后再次发现；重名和失败清理沿用标准项目保护规则。
- 当雨课堂实时采集尚未收到首张真实课件时，应用不得为书架生成占位 PDF；收到并建成标准项目后才加入书架。
- 已存在于绑定目录外的项目或历史文档缓存不自动复制、移动或伪装成绑定目录内的书籍，原有最近文档入口保留。

## R5 桌面适配与精简验收

- Windows 和 Mac 应共用书架 UI 与核心逻辑，沿用现有语言和主题设置；操作按钮应有可访问名称，图标应有提示。
- Mac 仅构建 arm64，并在 `release/mac-arm64/pagenote.app` 完成实际入口验证：正常保存退出、更新包、核对包时间、重开确认。
- 定向测试应覆盖目录扫描与安全边界、Android 封面元数据兼容、新建/导入自动入架、返回保存及启动恢复，不扩张为全环境测试矩阵。
- 使用隔离项目验证 Markdown 与真实 PDF 封面、搜索/列表切换、封面修改及目录更换，避免改动用户现有项目。
- 本机无法实测 Windows 时，应记录为未验证，不将共享代码测试或交叉打包称为 Windows 运行验收通过。
- 本轮只更新本地开发构建和 Unreleased 记录，不发布新公共版本，也不改公开下载链接。

## 非目标

- 云同步、账号、自动搬迁旧文件、删除/归档项目、重写阅读器或 Office 编辑器。
- 修改 Android 已确认的书架行为；两端只共享兼容格式和设计约定。
- 自动合并不同路径下具有相同 manifest ID 的项目；不得因同名或同 ID 静默覆盖另一项目。

## 已确认的桌面适配决定

1. 普通启动显示书架，但双击项目仍直接进入阅读器。
2. 保留最近文档入口；目录外的旧项目不自动搬入书架。
3. Word/PPT 封面优先用已有预览，扫描时不启动 Office。
4. 复用 `Note` 和四种纸本颜色，不另行生成桌面专属设计。
