# 雨课堂全端接入需求

日期：2026-10-22（Asia/Shanghai）

状态：需求已确认，三端实现进行中。Mac arm64 已验证应用内面板和二维码图片展示；真实账号登录、课程选择及课堂采集仍待验证。

## 目标

用户在 pagenote 内登录标准雨课堂 `https://www.yuketang.cn`，选择课程或正在进行的课堂，将可见课件导入标准项目；上课时新展示一页即自动追加一页，后台完成页面解析，保留用户笔记、批注与笔迹。

现有 Windows、macOS、Android 均纳入终态范围，先验证 Mac。Windows / macOS 复用桌面主体，macOS 仅构建 arm64；Android 保持原生 Kotlin / Android 14，小米平板 5 Pro 为重点设备。

## R1 应用内官方登录

- 当用户选择登录雨课堂时，pagenote 应在应用自身的登录窗口或内嵌页面中显示雨课堂官方登录流程及二维码。
- 当官方登录需要微信扫码确认时，pagenote 应等待该官方确认流程完成，并在应用内呈现成功、取消、过期或失败状态；不得将“应用内登录”解释为免去官方身份确认。
- 当用户完成登录时，pagenote 应将应用自身获得的会话交给课程获取和课堂连接模块，不要求用户复制 Cookie、安装浏览器插件、打开外部浏览器或导入 Edge / Chrome 的登录状态。
- 当官方登录过程涉及页面跳转时，pagenote 应在应用自身受控登录上下文内处理官方认证页面；遇到当前无法完成的流程应明确报告，不静默改为外部浏览器采集方案。

## R2 会话生命周期

- 当应用重启且本机会话仍有效时，pagenote 应复用本机会话并重新校验身份；失效时回到应用内登录流程，保留已下载项目与用户笔记。
- 当用户退出雨课堂账号时，pagenote 应清除应用自身的该账号认证会话，停止相关实时连接和未完成的认证请求；若课堂页面仍待写入，应保留认证和重试入口并说明原因，已导入本地课件保持可读。
- 当用户切换账号时，pagenote 应隔离原账号会话与课程任务，避免将一个账号的请求混入另一个账号。
- 会话仅保留在应用本机适当的安全存储中，不写入项目、导出包、日志、AI 提示词或版本库；各端独立登录，不读取系统浏览器凭据库。

## R3 课程与历史课件

- 当应用内登录有效时，pagenote 应分别列出该账号可访问的历史课件与当前正在进行的课堂；实时课堂不能依赖其先出现在历史列表中。
- 当用户选择正在进行的课堂时，pagenote 应显示其匹配课程；无法将课堂标识关联到账号课程时，不得静默使用另一个课程的来源信息。
- 当用户导入历史课件时，pagenote 应允许选择导入目标项目或目录。
- 当用户导入历史课件时，pagenote 应按可见课件的原始页序获取页面，排除播放时间线中的重复与懒加载占位图；校验成功后才呈现为完整导入。
- 当账号权限不足、图片缺失或接口结构变化时，pagenote 应区分原因并显示可恢复错误，不将空列表或部分下载标为完整成功。

## R4 实时逐页采集

- 当用户选择正在进行的课堂并启动实时采集时，pagenote 应使用应用自身会话建立课堂连接，在进入行为可能记录签到时清楚呈现这一含义。
- 当雨课堂新展示一个尚未采集的可见课件页时，pagenote 应下载并校验其页面资源，再为当前项目追加页面及对应笔记位置；不等待课后完整课件才能导入。
- 当老师翻回已采集且内容未改变的旧页时，pagenote 应识别为已有页面，不重复插入；同一课件页收到重复事件也不得多次追加。
- 当老师更换课件或已采集页内容改变时，pagenote 应记录来源身份与版本，不将新内容错误绑定到同页号的旧笔记或笔迹，也不静默覆盖用户编辑。
- 当后台 OCR 正在处理已有新页时，后续页面采集应能继续；OCR 失败应保留原图并报告，可重试而不重复追加页面。
- 页面身份至少包含课堂、课件和稳定页面标识；远端 ID 使用字符串。首版建议按首次成功展示的顺序追加并记录原课件页号，具体映射在设计中固定。

## R5 连接与阅读互不打断

- 当新页到达而用户正在其他页书写或编辑时，pagenote 应保留当前页、草稿、选区及笔迹；实时采集与自动跟页为独立状态。
- 当网络断开时，pagenote 应显示断开状态并保留已采集内容；重连后根据平台可返回的时间线和页面数据尝试补采，无法恢复的缺页明确标记。
- 当课堂结束或用户停止采集时，pagenote 应正常结束连接和队列收尾；失败页面须继续可重试，写入完成前不能切换课堂或退出账号，已完成的本地项目仍可离线打开。

## R6 跨端与解析

- 当任一端打开已导入项目时，pagenote 应识别相同的来源清单和页面映射，保留源文档、分页笔记、批注与笔迹的对应关系。
- 当 PDF 只有图片且没有原生文字层时，pagenote 应使用各端现有离线 OCR / 页面准备模块，保留原图、置信度和警告，不宣称无损提取公式、表格或图表。
- 当用户启用 AI 讲解时，pagenote 应对准备好的页面使用其已配置的模型连接；登录凭据不进入模型请求。
- 从雨课堂到本地的课件更新不等于跨设备实时同步笔记；本轮不自动引入账号云同步或自建网关。

## 精简验收与完成边界

- Mac 实际打包应用内完成一次官方登录、课程选择和历史课件导入；测试不依赖 Edge / Chrome 登录态。
- 用真实进行中的课堂验证新页追加、旧页回翻去重、停止采集；真实课堂认证与事件尚未验证时，不以模拟事件测试宣称实时接入成功。
- 用同一批脱敏样本覆盖重复事件、断线补采、课件切换和已有笔记保护；不重复扩张平台组合矩阵。
- Windows 和 Android 复用公共契约分别完成一次最小闭环；Android 日常使用 API 34 平板 AVD。
- 先前 82 页 Mac 试验仅证明浏览器会话采集后的导入与 OCR，不满足 R1、R2、R4 的完成条件，见 [试验记录](mac-feasibility-2026-10-22.md)。
