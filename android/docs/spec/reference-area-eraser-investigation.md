# 参考应用区域橡皮调查

`EraseAction` 同时遍历 `Pen` 和 `ShapeTool`。相交的自由笔迹调用笔型切分方法，图形调用 `ShapeTool.split`，将擦除前后材料归入同一个动作。

`CircleTool.split` 将圆形轮廓采样为笔迹后调用 `split_v2`；`BezierTool.split` 用 `PathMeasure` 沿曲线取点后调用相同切分路径。参考实现的橡皮可视范围默认为圆角矩形或自定义图片，而当前 PageNote 使用圆形擦除区域，因此本轮显示的圆形边界准确对应现有擦除半径，不宣称形状与参考一致。

进一步对照 `CircleTool.split` 和 `Utils.pointDistanceN`：第一个点是圆心，两点的欧氏距离是半径；角度步长为 `max((int)(50 / sqrt(radius)), 2)`，从 0 度采样到包含 `360 + step`，再转换成笔迹送入切分。`Pen.split_v2` 使用扩展后的两个橡皮矩形及其连接区域，沿每条笔迹线段按单位距离取点。该行为不同于当前的圆形扫掠算法，不能用当前算法冒充参考实现。参考的圆也不能直接当作 PageNote 的任意椭圆：其点语义不同。

`ReferenceCircleOutline` 仅移植了圆轮廓采样，单元测试覆盖角度步长及退化圆；目前没有接入橡皮或页面交互，也没有声称完整移植 `split_v2`。其输入必须先从项目文件图形明确转换成参考圆心与边界点，且必须解决混合编辑事务后才可用于用户数据。

`ReferencePenSplit` 是 `Pen.split_v2` 和 `PanelUtils.rectToRegion` 的隔离几何移植：调用 Android 的 `Region` 与 `PathMeasure`，保留原流程的整型坐标和线段逐单位采样。现已根据 `Pen.buildPathFromPoints`、`PathHelp.onTouch` 和 `PanelUtils.pointsToRect` 补充默认未平滑模式的包围盒生成，并在 `ReferenceCircleSplit` 中串起圆形采样、包围盒和切分；片段宽度使用参考的 `strokeWidth * autoShapeLineFactor * 1.2`。Android 14 模拟器定向测试覆盖穿过、完全覆盖、未命中、长距离扫掠和圆形切分，尚未与参考程序做逐点差分。

该代码复制传入包围盒，不复现参考源码中 `Rect.intersect` 对原线段包围盒的原地修改；参考材料对象、其他平滑模式、压感、颜色透明度、图形类型、坐标尺度、连续手势与历史事务仍需适配，不能视为完整的 `split_v2` 实现。参考圆形使用圆心和半径点，PageNote 的椭圆使用包围盒对角点，不能直接套用。它没有接入阅读器，也不会修改用户文件。

PageNote 的识形结果保存在矢量批注层，自由笔迹保存在独立内存模型；混合擦除必须在同一手势中统一快照、更新显示、保存和撤销。早期将矢量拆分后单独异步保存的实验会产生撤销不同步、扩展数据与片段数量问题，已撤出产品代码，实验记录保留在本机参考项目的 `handwriting-kernel/erase-prototype/`。下一步需要先完成统一事务与失败回滚，再按参考源码恢复各图形的切分方式，验证项目文件往返及真实设备交互。

现有混合历史的撤销和重做已增加锁内磁盘快照比对：页面内容或笔迹与批注的相对顺序变化时拒绝写回并恢复历史指针；JSON 数值格式差异不会单独触发冲突。笔迹保存会调整两层之间的顺序，因此即使内容相同也可能被保守地拒绝。该锁只协调本进程，不提供跨应用原子比较写入。**尚未同步混合恢复后的内存笔迹，也未覆盖写入期间产生的新输入、失败待重试快照或统一两套历史**，因此不能作为图形擦除事务的完整实现。单元测试覆盖快照匹配和冲突，真实混合历史交互仍需验证。

内存同步实验经独立复核后撤回：直接 `reloadPage` 会清空已有笔迹重做历史；坐标和压力经过 Float 解析可能改变原始值；补偿写入无法保证与其他应用的修改原子隔离。实验保留在参考目录的 `handwriting-kernel/mixed-history-prototype/`，不参与构建。

参考 `EraseAction` 在手势前后分别保存页面材料列表，撤销和重做恢复同一动作的前后状态。为对接这一动作粒度，`PageEditTimeline` 是尚未接入阅读器的顺序协调实验：区分笔迹、批注和同时影响两者的动作；在底层历史修改期间占用页面操作槽；失败但仍显示在画布上的笔迹必须作为保留动作记录。它按页限制 80 项、对未完成动作施加背压，以稳定动作 ID 支持页码映射；有未完成动作时拒绝清空或映射，调用方仍需在项目切换时取消或等待旧操作并隔离旧回调。该实验不读写用户项目、不提供页面快照，也不等同于参考代码的完整移植。

接入前仍须让实际快照与动作 ID 一一对应并按同一顺序提交：当前 `PdfAnnotationEditHistory.record` 会因中间笔迹保存导致整页不相等而清空较早批注历史，单靠时间线不能修复；`PenPageStore.reloadPage` 会清空笔迹历史；失败待重试保存和跨应用 SAF 竞争也需要处理。新动作成功时两套底层 redo 必须一起失效，而失败时须保留；时间线本身不会处理底层栈。页面操作槽只能覆盖短暂的内存模型和历史提交，不能跨耗时 SAF 写入占用，否则会阻塞连续书写；磁盘保存需要独立有序队列和明确的失败处理。实例必须与项目会话绑定，页码变动时要同步迁移底层快照；当前每页上限不提供项目总内存上限。需完成实际阅读器混合操作、撤销重做、继续书写、失败恢复与重开项目的集成验收。
