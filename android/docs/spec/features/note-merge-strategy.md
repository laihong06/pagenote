# Android 笔记合并对话框与策略（页序/冲突/资产去重）

**Status:** 已实施（分支 `codex/port-canvas-notes-features`，移植差距清单 #15 的 Android 侧增强）。
桌面 JSON 导入是"按页码整页覆盖"；本契约在 Android 导入合法 JSON 备份后提供合并策略。

## 行为

- 导入 JSON 备份（`File > Import notes`，检测规则不变）解析成功后，弹出合并对话框替代原确认框：
  - 摘要行：导入页数、冲突页数、资产引用去重后数量与总引用数。
  - **页序**：`按页码对齐`（默认，桌面等价行为）或 `追加到笔记末尾`（仅 Markdown 项目可选；PDF 项目笔记页数跟随源页数，追加会产生不可达页，选项禁用且应用层兜底强制对齐）。追加模式把导入页按原页码升序接到当前笔记文档末尾，空内容页跳过。
  - **冲突处理**（目标页与导入页均为非空且不同时生效）：`导入内容覆盖当前`（默认）/ `保留当前内容`（导入仅填充空白页）/ `合并内容`（当前在前、导入在后，以空行分隔）。导入页为空字符串时视作"清空该页"的覆盖意图；保留策略下不改动该页。
  - 确认按钮沿用既有文案；取消不写入任何内容。
- **资产去重**：导入内容中 `assets/<uuid>.<ext>` 引用跨页去重并汇总（与 `ProjectAssetRefs` 同一契约）；已在当前笔记中引用过的资产不计入新增。JSON 备份不携带资产字节，合并只处理 Markdown 引用，不复制或改写资产文件。
- 合并写入沿用既有事务：revision 锁内读取最新笔记 → 按策略合并 → 单次可恢复 SAF 写入 → 变更页写历史镜像 → 整本重读入搜索索引。成功后扫描合并结果引用的资产，若项目 `assets/` 缺失则明确报告缺失清单（不静默保留悬空引用）。
- 上下文失效（项目/页面/笔记变化）与冲突/写入失败的处理与 note-import 契约一致；失败不报告成功。
- 越界页处理随策略变化：对齐模式沿用"跳过 1..源页数之外"的旧规则；追加模式保留全部合法页（这正是追加的存在意义）。备份结构校验（`notes` 对象、字符串值、十进制页键）不变。
